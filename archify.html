Architecture Patterns & Key Benefits

1. Cache-Aside (Lazy Loading) Application code first queries the cache. If data is missing (miss), application reads from PostgreSQL and populates the cache for subsequent readers.
2. Database Load Reduction Subsequent calls bypass PostgreSQL completely, reducing query pressure on PostgreSQL connection pool (`pg.Pool`) by over 90%.
3. Multi-Tenant Cache Keying Cache keys include hotel names (e.g. `hms:rooms:{hotel_name}`) ensuring total data isolation between different hotel staff administrator accounts.
